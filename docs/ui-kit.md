# UI Kit и правила проектирования интерфейса Nodaris

Документ определяет единые правила проектирования интерфейса на Svelte 5 (Tauri / Web).

## 1. Главный принцип
> **Сначала семантика и поведение, затем визуальное оформление.**
Компонент должен иметь понятную ответственность, предсказуемое состояние и корректную HTML-семантику.

## 2. Архитектура интерфейса
```text
Page (оркестрация, загрузка данных)
 └── Feature (доменная логика: карта сети, сканер Wi-Fi)
      └── UI (универсальные компоненты: Button, Modal, Table)
```

* **Page**: не содержит верстки универсальных компонентов.
* **Feature**: знает о `AccessPoint`, `BSSID`, `RSSI`. Не создает свои `Button`.
* **UI**: ничего не знает про сеть. Только `variant`, `size`, `disabled`.

## 3. Svelte 5 и реактивность
Проект использует Svelte 5. Забудьте про `$:` и `export let`.
* Состояние: `let value = $state(0);`
* Производные: `let double = $derived(value * 2);`
* Эффекты: `$effect(() => { ... });`
* Пропсы: `let { variant = 'primary', disabled = false } = $props();`

## 4. Design Tokens (app.css)
Запрещено хардкодить цвета и отступы.
```css
:root {
    /* Сетка цветов */
    --color-bg: #0d1117;       /* Темный фон */
    --color-surface: #161b22;  /* Карточки */
    --color-primary: #00d2ff;  /* Акцент (из логотипа) */
    --color-text: #c9d1d9;
    --color-danger: #f85149;
    
    /* Сетка отступов (шкала 4px) */
    --space-1: 4px;
    --space-2: 8px;
    --space-3: 16px;
    --space-4: 24px;
}
```

## 5. Состояния (Loading / Empty / Error)
Для сетевых инструментов это критично.
* **Loading**: Скелетоны (skeleton) для таблиц. Спиннеры только для кнопок.
* **Empty**: "Сети не найдены. Проверьте адаптер".
* **Error**: Использовать компонент `<Alert>` с `translateError()`.
* **Refreshing**: Если данные уже есть, не сбрасывайте их в ноль при обновлении. Показывайте индикатор поверх старых данных.

## 6. Специфика Nodaris (Сеть)
* **Таблицы**: Для списка точек доступа используйте `<div class="table-scroll">` с `overflow: auto`. Широкие таблицы не должны ломать layout страницы.
* **Графики (Chart.js)**: Используйте `$derived` для вычисления точек. Цвета линий (RSSI, SNR) берите из Design Tokens.
* **Иконки**: Для статусов (Подключено, Ошибка, Сканирование) используйте единый компонент `<Icon name="..." />`.

## 7. Формы и валидация
Каждый input должен иметь `<label>`. Ошибки — строго под полем.
```svelte
<label for="ip">IP Address</label>
<input id="ip" aria-invalid={!!error} aria-describedby="ip-error" />
{#if error}
    <div id="ip-error" class="text-danger">{translateError(error)}</div>
{/if}
```

## 8. Layout и Overflow
Частая проблема сетевых дашбордов — разъезжающаяся верстка.
* Используйте `display: flex; flex-direction: column; height: 100vh;` для корня.
* Для основной рабочей области: `flex: 1; min-height: 0; overflow-y: auto;`.
* **Правило**: `overflow: hidden` нельзя ставить просто так. Сначала определите, где должен быть скролл (в таблице, в панели, во всем окне).

## 9. Правило трех (Rule of Three)
Если вы пишете одинаковый код 3 раза — выносите в компонент. Но если это просто `div` с `display: flex`, возможно, достаточно CSS-класса `.flex-row`.

## 10. Accessibility (A11y)
* Все кликабельные элементы: `<button>` или `<a>`.
* Иконки-кнопки (например, "Обновить"): `<button aria-label="Refresh"><Icon name="refresh"/></button>`.
* Модальные окна (Tauri): Обязательно управляйте фокусом. При открытии фокус внутри, при закрытии — возвращается на кнопку, вызвавшую модалку.
* Tab-навигация: Кнопки "Сканировать", "Настройки" должны работать по Enter/Space.
